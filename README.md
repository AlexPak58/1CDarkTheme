# Настройка цветов Конфигуратора 1С

Фоновое приложение в трее Windows 11 применяет выбранные файлы пресетов
к открытым и новым сеансам Конфигуратора поддерживаемой сборки
`8.3.27.2325 x64`. Другие сборки Конфигуратора и сеансы «1С:Предприятие»
отображаются на вкладке «Открытые сеансы» в режиме обнаружения.

## Сборка и запуск

Для сборки нужны Visual Studio с инструментами C++ x64 и .NET 10 SDK.
В **x64 Native Tools Command Prompt for Visual Studio** выполните:

```bat
build.cmd build settings
```

1. Откройте `build\ConfiguratorThemeSettings.exe`. На другом ПК нужен
   .NET 10 Desktop Runtime x64. Переносите приложение вместе с файлами
   `.dll`, `.deps.json`, `.runtimeconfig.json`, лаунчером `tree-theme-run.exe`,
   DLL темы `tree-theme.dll` и каталогом `presets` из выходного каталога.
2. На вкладке «Общие настройки» выберите JSON-файл темы по умолчанию и
   нажмите «Применить». Вкладка «Открытые сеансы» показывает обнаруженные
   процессы, выбранный для каждого файл и состояние применения.
3. Закройте окно, чтобы оставить приложение в трее. Для возврата к окну
   выберите «Настройки…» в меню значка. Чтобы запускать приложение при
   входе в Windows, включите соответствующий флажок в общих настройках.
   Аргумент `--tray` запускает приложение со скрытым окном.

Пункт «Приостановить тему» выключает фоновое применение и возвращает
штатные цвета в поддерживаемых сеансах. Для отдельной базы можно назначить
файл `native.json`. По команде «Выход и вернуть штатные цвета» приложение
останавливает наблюдение и пытается вернуть штатные цвета в затронутых
открытых сеансах. Если часть сеансов восстановить не удалось, приложение
сообщит об ошибке.

## Файлы настроек и пресетов

По умолчанию данные хранятся в `%LOCALAPPDATA%\1CDarkTheme`.
Переменная окружения `ONEC_DARK_THEME_DATA` задаёт другой каталог данных.
При запуске приложение создаёт `config.json`, если файл отсутствует,
и копирует недостающие стандартные пресеты из комплекта в подкаталог
`presets`. По умолчанию выбрана тёмная палитра. В комплект входят
[тёмная](presets/dark.json), [графитовая](presets/graphite.json),
[нежно-розовая](presets/pink.json) палитры и [штатные цвета](presets/native.json).

На вкладке «Редактор файла пресета» откройте нужный JSON, включите зоны
и задайте цвета в формате `#RRGGBB`. Сохраните изменения в открытый файл
или выберите «Сохранить как…» и назначьте новый файл в общих настройках
либо в правиле. Название внутри JSON служит подписью. Палитру определяет
путь к файлу.

При очередном обходе приложение проверяет изменения сохранённых файлов
и применяет выбранный пресет к уже открытым поддерживаемым сеансам.
Если файл настроек или выбранный пресет отсутствует либо содержит ошибку,
приложение показывает ошибку и сохраняет ранее применённую палитру.

Пресет хранится отдельным JSON-объектом с полями `schemaVersion`, `name`,
`paletteVersion`, `mask` и `colors`. Текущий формат использует `schemaVersion: 1`,
`paletteVersion: 8` и 37 цветов. При чтении палитр версий 1–7 сохраняется
исходный набор включённых зон, а недостающие цвета берутся из тёмной
палитры. Максимальный размер каждого файла настроек или пресета — 1 МиБ.

Зона «Разделители панелей» задаёт отдельный цвет поддерживаемых широких
разделителей Конфигуратора 8.3.27.2325. В старых файлах
эта зона остаётся выключенной; её можно включить и сохранить в редакторе.

## Исключения для баз, платформ и режимов

На вкладке «Общие настройки» задайте нужные поля исключения, выберите
файл и нажмите «Добавить / заменить». Для серверных баз укажите
`server:СЕРВЕР\БАЗА`, для файловых — `file:полный путь к каталогу базы`.
Платформа задаётся точной версией и разрядностью, например `8.3.27.2325-x64`.
В файле настроек режимы записываются как `Designer` и `Enterprise`.
Пустое поле в форме или `null` в JSON подходит под любое значение.
В каждом исключении задайте хотя бы одно условие.

Если подходят несколько правил, указанные база, платформа и режим дают
соответственно 4, 2 и 1 балл. Применяется правило с наибольшей суммой.
Если база неизвестна, рассматриваются правила без базы. При отсутствии
совпадения применяется файл по умолчанию. Чтобы удалить исключение,
выберите его в таблице и нажмите «Вернуть общие настройки».

В примере `config.json` относительные пути вычисляются от каталога этого
файла. Можно также указать полный путь к пресету.

```json
{
  "schemaVersion": 1,
  "enabled": true,
  "defaultPresetFile": "presets/dark.json",
  "rules": [
    {
      "baseId": "server:SERVER\\DEMO",
      "platform": "8.3.27.2325-x64",
      "mode": "Designer",
      "presetFile": "presets/pink.json"
    }
  ]
}
```

## Области оформления

Доступны фон и подписи обоих деревьев, заголовок окна, верхнее меню и
участки панелей инструментов, палитра свойств, рабочая область, строка
состояния и обе полосы вкладок. Фон справа от кнопок настраивается
отдельно, в зоне «Свободная полоса за кнопками». Для тонких контуров
есть зона «Рамки верхнего меню и групп кнопок» с общим цветом. У выпадающих
меню можно настроить фон, полосу значков, подписи обычных пунктов и горячие
клавиши. Зона «Результаты поиска» задаёт фон и текст обычных строк
поиска объектов метаданных. В DLL добавлен отдельный фильтр глобального
поиска по текстам: он использует те же два цвета и автоматически
подхватывает компонент поиска после его загрузки. На BPDemo проверены
выдача по свойствам, выделение, переход к свойствам и отключение зоны.
Длинная выдача и остальные типы глобального поиска требуют проверки. При поздней
загрузке компонента первый кадр может оставаться светлым до проверки
модуля и перерисовки. Встроенные пресеты «Тёмная»,
«Графитовая» и «Нежно-розовая» включают эти зоны.

Зона «Рамки и заголовки панелей» задаёт фон локальной рамки и цвет
заголовка пристыкованных панелей и дочерних окон. Она проверена на BPDemo
для дерева конфигурации, расширения, свойств, результатов поиска и окна
модуля. Тот же цвет текста применяется к подтверждённым значкам кнопок
на этих заголовках. Цвета редактора BSL сохраняются. В профиле v7 добавлено
поле «Наружная рамка панелей» для контура дочерних окон и поддерживаемых
веток рамок панелей. На BPDemo проверены отдельный цвет, сохранение через
интерфейс, отключение зоны и восстановление/максимизация окна модуля.
Толстые разделители между панелями не покрыты этим полем.
В пресете версии 1–5 зона после миграции остаётся выключенной, её можно
включить отдельно и сохранить файл. Для v6 сохраняется прежняя маска зоны.

Выпадающие списки исследованного типа включаются отдельно. Проверены
«Назначение расширения» и «Основной режим запуска». Наружные рамки,
разделители панелей, полосы прокрутки, пояснение свойств,
счётчик и линии результатов ещё не имеют полного оформления. Кнопки MDI,
перенесённые в главное меню при максимизации, также требуют отдельной доработки.
Поля ввода, содержимое диалога поиска и выделение строк результатов используют цвета
платформы. Цвета совпадений и выделения в деревьях, редактора BSL,
подсветки пункта меню и других диалогов также задаёт платформа.

## Консольный режим

Консольный режим запускает отдельный сеанс для ручной проверки.
Чтобы проверить только консольное применение, завершите фоновое
приложение через меню трея.

Откройте **x64 Native Tools Command Prompt for Visual Studio** и выполните
`build.cmd`. Результаты сборки находятся в каталоге `build`.
Чтобы собрать ещё один комплект рядом с уже запущенным, укажите
отдельный каталог, например `build.cmd build\caption`.

Запустите лаунчер с явным путём к платформе и проверенной тестовой базой:

```powershell
.\build\tree-theme-run.exe '<путь к 1cv8.exe>' '<сервер>\<база>'
```

Для отдельной проверки заголовка на Windows 11 добавьте аргумент
`--caption`. Лаунчер применит цвет фона и текста заголовка через DWM
вместе с темой дерева. Для этого должно быть ровно одно видимое,
не принадлежащее другому окну окно процесса со стандартным заголовком.
Команды `d` и `q` возвращают заголовку системные цвета по умолчанию.

Экспериментальный аргумент `--bars` перекрашивает верхнее меню и участки
панелей инструментов. Выпадающие пункты используют цвета платформы.
`--bars` можно сочетать с `--caption`.

Аргумент `--status-bar` включает тёмный фон и светлый текст строки
состояния внизу Конфигуратора. Его можно использовать вместе с `--bars`
или отдельно от него.

Аргумент `--window-tabs` включает тёмный фон нижней панели открытых
окон и светлые подписи на вкладках. Активная вкладка выделяется синим фоном.

Аргумент `--tree-tabs` включает тёмную панель под деревом конфигурации,
светлые подписи вкладок конфигурации и расширения и синий фон активной
вкладки. Его можно использовать вместе с `--window-tabs`.

Аргумент `--search-results` добавляет к теме дерева тёмный фон списка
результатов поиска по конфигурации и светлый текст обычных строк.
Введите `e` в консоли лаунчера и выполните поиск по конфигурации.

Аргумент `--properties` включает тёмный фон таблицы палитры «Свойства»,
светлые подписи и свою заливку выделенной строки. Поля ввода и поиска,
а также цвет текста найденного фрагмента задаёт платформа.

Аргумент `--workspace` затемняет пустую рабочую область Конфигуратора,
в том числе фон вокруг открытых окон. Редактор модулей сохраняет свои
цвета фона и подсветки из настроек Конфигуратора. Аргумент можно сочетать
с `--properties` и другими аргументами темы.

Откройте дерево в запущенном Конфигураторе. В консоли лаунчера введите
`e`, затем смените выделение или вкладку, чтобы перерисовать дерево.
`d` возвращает штатные цвета при следующей перерисовке. Для
перерисовки рабочей области, строки состояния, вкладок, панелей и палитры после `e` или `d`
измените размер окна.
`q` выключает
тему и завершает лаунчер. Закройте запущенный Конфигуратор, чтобы полностью
выгрузить DLL и отменить изменения в памяти процесса.

Лаунчер загружает DLL в созданный им экземпляр Конфигуратора. DLL сверяет
SHA-256 платформы и байты инструкций перед подключением обработчика.
Прототип использует программные точки останова и обработчик исключений
внутри процесса. Отладчик не требуется. Сравнение с IAT для деревьев и
границы этого замера описаны в [RESEARCH.md](RESEARCH.md).

## Трассировка палитры свойств

Ход экспериментов, адреса стека и план проверки режима «1С:Предприятие»
собраны в [RESEARCH.md](RESEARCH.md).

`trace-paint.cdb` содержит четыре одноразовые точки останова для
`8.3.27.2325 x64`. Перед применением сверьте SHA-256 `frame.dll` и
`grphcs.dll` с `platform.hpp`. Используйте отдельный тестовый
Конфигуратор без DLL темы. Подготовьте вид в интерфейсе, подключите
CDB к PID этого процесса и выполните `$$><trace-paint.cdb` из каталога
проекта. Вызовите одну перерисовку, затем прервите выполнение в CDB
и отсоединитесь командой `qd`. Повторите с открытой палитрой и при
переключении активной ячейки. Сравните стеки и исходные цвета.

Заливка строк, групп и выделения проходит через `grphcs+0xAEE4E`.
Подписи и ссылки проходят через `grphcs+0x22D7`. DLL сверяет адреса
возврата и исходный цвет для каждой замены. Адреса приведены в
`propertyFillColor` и `propertyLabelColor` в `theme.cpp`.
